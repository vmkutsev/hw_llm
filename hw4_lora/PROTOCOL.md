# Протокол сравнения

## Выбор данных

Исходный Amazon ESCI содержит размеченные пары «поисковый запрос — товар». Взяли два опубликованных Parquet из ревизии `7916cdf6ab75a462e77f20ab40428a10923998d5`. В подготовке проверяются размер файла и SHA256. [Источник](https://github.com/amazon-science/esci-data/tree/7916cdf6ab75a462e77f20ab40428a10923998d5) · [Статья о данных](https://arxiv.org/abs/2206.06588) · [Лицензия Apache-2.0](https://github.com/amazon-science/esci-data/blob/7916cdf6ab75a462e77f20ab40428a10923998d5/LICENSE) · [Код подготовки](prepare.py)

1. Применяем фильтры `product_locale='us'` и `small_version=1`. Вторая метка соответствует версии, которую авторы подготовили для ранжирования.
2. Для проверки пересечений нормализуем запрос через Unicode NFKC, casefold и свёртку пробельных символов. Исключению подлежат пустые ключи, ключи нескольких групп и запросы с повтором одного и того же товара. Число исключений для этой ревизии записано в манифесте.
3. Внутри опубликованных train и test сортируем группы по SHA256 строки `42:query-{split}:{нормализованный запрос}`. Из train первые 600 запросов идут в обучение, следующие 128 в validation. Из test берём первые 256 запросов. Сохраняем полный исходный список для каждого выбранного запроса.
4. Присоединяем заголовок по ID и локали товара. Проверяем уникальность ID пар, отсутствие пересечений запросов и полноту списков. Товар может участвовать в нескольких разных запросах. Эксперимент проверяет перенос на новые запросы внутри того же каталога. [Манифест выборок](results/dataset_manifest.json)

## Обучение и оценка

Используем `Qwen/Qwen2.5-1.5B-Instruct` из ревизии `989aa7980e4cf806f80c7fef2b1adb7bc71aa306`. Родной chat template получает инструкцию на английском с определениями четырёх классов и JSON с запросом и заголовком. Каждый класс задаётся одной буквой E/S/C/I. Код проверяет, что в контексте первой позиции ответа ей соответствует ровно один токен. Длина ограничена 256 токенами. При переполнении укорачивается конец заголовка. [Карточка модели](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct) · [Инструкция, токенизация и обучение](experiment.py)

Целевая функция — cross-entropy первой буквы ответа по всему словарю языковой головы. При оценке берём softmax по четырём логитам E/S/C/I. Классом считаем argmax. Для ранжирования используем ожидаемый выигрыш `P(E) + 0.1·P(S) + 0.01·P(C)`. Тот же декодер используется для исходной Qwen, Full FT и всех LoRA.

- **nDCG@10.** Сортируем товары каждого запроса по ожидаемому выигрышу. При равенстве порядок определяется ID товара, затем ID пары. В DCG используем линейные выигрыши авторов ESCI (E = 1, S = 0,1, C = 0,01, I = 0) и скидку `1/log2(позиция+1)`, начиная с позиции 1. Делим DCG первых десяти товаров на идеальный DCG той же глубины для этого запроса. Усредняем по запросам с положительным знаменателем. [Определение выигрышей в статье, §3.1](https://arxiv.org/pdf/2206.06588) · [Реализация](metrics.py)
- **Macro-F1.** По всем парам части собираем матрицу «эталон × предсказание». Для каждого класса считаем `2 TP / (число эталонных + число предсказанных)` и усредняем четыре значения. При нулевом знаменателе вклад класса равен нулю. [Проверки на примерах с известным ответом](test_metrics.py)

Общая настройка обучения — 2 эпохи, batch 32, seed 42. Для эпохи с индексом `i` (начиная с 0) используем отдельный генератор перестановки с seed `42+i`. AdamW fused, LR `5e-5`, betas `0.9/0.999`, eps `1e-8`, weight decay `0.01`, clip norm 1. Линейный warmup занимает первые 6% шагов с округлением вверх, затем LR линейно снижается. Веса и состояния оптимизатора в FP32, матричные операции под BF16 autocast, attention через SDPA. Все методы сравниваются при этом общем бюджете и LR.

Full FT обновляет все исходные параметры. В LoRA обучаются новые матрицы A и B. Исходные проекции, bias и языковая голова заморожены. Опорная конфигурация использует `r=8, alpha=16, dropout=0.05` и `q_proj,v_proj`. В четырёх опытах отдельно меняются ранг, alpha, dropout и набор слоёв. При расширении набора до семи проекций добавляются `k_proj,o_proj,gate_proj,up_proj,down_proj`. Дополнительный контроль использует `r=32, alpha=64` при тех же `dropout=0.05` и q/v. Относительно опорного запуска он сохраняет масштаб `alpha/r=2`. Сравнение с `r=32, alpha=16` сохраняет ранг, а сравнение с `r=8, alpha=64` сохраняет alpha. Стандартный масштаб равен `alpha/r`. При изменении ранга с фиксированной alpha меняется и масштаб, а при расширении набора слоёв растёт число обучаемых параметров. [Конфигурации](protocol.json) · [Документация PEFT](https://huggingface.co/docs/peft/v0.17.0/en/package_reference/lora)

## Сравнение вариантов

Каждое обучение идёт в отдельном процессе. Замер времени синхронизирован с CUDA и охватывает сборку batch, forward, backward и шаг оптимизатора. Загрузка файлов, токенизация и оценка выполняются за пределами измеряемого участка. Пик `torch.cuda.max_memory_allocated()` показывает объём памяти, выделенной под тензоры PyTorch на GPU в тренировочном цикле, в GiB. У исходной модели проводится только оценка, поэтому в графах тренировочных затрат стоит прочерк.

Лучший вариант LoRA выбираем по validation nDCG@10. При равенстве выбираем по validation macro-F1. Для оценки разностей на тесте применяем парный bootstrap по запросам с 2 000 повторов и seed 20261105. Все товары одного запроса остаются вместе. В каждом повторе пересчитываем обе метрики на одном и том же наборе запросов для двух моделей. Берём квантили 2,5% и 97,5%. Это интервалы для состава тестовых запросов при одном seed обучения. Поправка на множественные сравнения не применялась. [Код сверки и интервалов](analyze.py)

Для ручного разбора заранее фиксируем восемь тестовых пар, по две на каждый класс и по одной на запрос. Внутри класса порядок задаёт SHA256 от seed, префикса `manual` и ID пары. Сравниваем исходную модель, Full FT и заранее выбранную опорную LoRA по предмету запроса, его ограничениям и отношению товара к запрошенному. Отмечаем случаи, где по одному заголовку можно защитить несколько трактовок. Этот набор иллюстрирует типы ошибок. Для общей оценки используем все 5 285 пар из 256 тестовых запросов.
